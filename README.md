# MiniToo Studio (Rust)

Переписанная на Rust версия MiniToo Studio — приложения, которое выводит на экран колонки
**Divoom MiniToo** (LCD 160×128, Bluetooth SPP) картинки и GIF, трансляцию области экрана, «живые»
режимы (часы и погода, системный монитор, «сейчас играет», Pomodoro, статистика Claude Code,
GitHub Actions, визуализатор звука), уведомления рабочего стола и статус Claude Code. Поведение,
тексты и внешний вид — по `SPEC.md`; эталон — C++/Qt-версия в `/home/spike/projects/divoom`.

## Почему Rust, а не Go

| Критерий | Rust | Go |
|---|---|---|
| Захват экрана и звука на Wayland | официальные биндинги `pipewire-rs`, портал ScreenCast с `restore_token` — `ashpd` | зрелых биндингов PipeWire нет, только свой cgo |
| zstd с параметрами колонки (`windowLog = 17`, размер в заголовке) | `zstd` — та же libzstd, что у эталона, параметры задаются напрямую | `klauspost/compress` — своя реализация, окно и заголовок контролируются хуже |
| D-Bus (уведомления через `BecomeMonitor`, BlueZ, MPRIS, блокировка, трей KDE) | `zbus`, `ksni`; для монитора уведомлений — свой минимальный клиент, чтобы ничего не отправлять после `BecomeMonitor` | `godbus` — сопоставимо |
| Интерфейс «под колонку» (пластик, клавиши с ходом, пиксельный текст) | `egui`: каждый элемент рисуется вручную, Linux/Windows/macOS | Fyne/Gio: свой рисованный стиль заметно сложнее |
| Реальное время (RFCOMM, 20 к/с трансляции, FFT каждые 60 мс) | нет сборщика мусора, предсказуемые задержки | паузы GC, обычно некритичные |
| Окружение | Rust уже установлен на хосте; ставить на хост ничего нельзя | Go на хосте нет |

Итог: Rust закрывает все системные интеграции спецификации готовыми библиотеками, а Go
потребовал бы писать биндинги PipeWire и сам интерфейс почти с нуля.

## Сборка

В контейнере, на хост ничего не ставится (как и у эталона):

```bash
./build.sh            # release-сборка и тесты → build/minitoo-studio
./build.sh --windows  # плюс проверка типов под Windows (x86_64-pc-windows-gnu)
```

Если Rust уже есть на машине, можно и напрямую: `cargo build --release`, `cargo test --lib`.
Для Linux нужны заголовки PipeWire и clang (bindgen); на Arch/CachyOS они в пакетах `libpipewire`, `clang`.

## Запуск

```bash
./build/minitoo-studio              # окно + значок в трее
./build/minitoo-studio --hidden     # сразу в трей
./build/minitoo-studio --headless   # без окна и трея: колонка + HTTP API
./packaging/install-desktop.sh [--autostart]   # ярлык KDE (--uninstall — убрать)
```

Командная строка, HTTP API (`127.0.0.1:47800`), хуки Claude Code, настройки
(`~/.config/minitoo-studio/minitoo-studio.conf`) и галерея
(`~/.local/share/minitoo-studio/MiniToo Studio/gallery/`) — те же, что у Qt-версии: конфигурация
и галерея подхватываются без переноса.

## Языки

Интерфейс на русском и английском; язык, формат времени (24/12 ч) и даты выбираются в
«Настройки → Язык и форматы». Тексты лежат в `locales/*.lang` — свой перевод делается копией
`en.lang` в `~/.config/minitoo-studio/locales/<код>.lang`, подробности в `locales/README.md`.

## Устройство

```
src/
  protocol.rs      кадр сообщения, разбор ответов, кодирование медиа (zstd), пакеты (§2)
  transport.rs     RFCOMM: сокет AF_BLUETOOTH (Linux), AF_BTH (Windows), последовательный порт (macOS)
  worker.rs        поток канала: подключение с паузами, очередь команд, «последний побеждает», keepalive (§5)
  app.rs           контроллер: модель «что на экране» (§4), Claude, блокировка, ротация, трансляция, HTTP-маршруты
  api.rs           контракт ядро ↔ интерфейс: неизменяемый Snapshot + Command
  live/            живые режимы (§8) поверх общего контракта LiveMode/ModeHost
  faces.rs, gif.rs сцены Claude (18 штук, попиксельно как в эталоне) и запись GIF
  media.rs, gallery.rs   загрузка картинок (png/jpg/gif/webp/apng/bmp/tiff/svg/jxl; avif/heic — через ImageMagick, если он есть), рендер 160×128, галерея
  canvas.rs, fonts.rs, pixelfont.rs, icons.rs   рисование кадров: DejaVu, ручной шрифт 5×7, иконки 12×12
  i18n.rs          языки (каталоги locales/*.lang, tr!/trn!), форматы даты и времени
  claude.rs        сессии Claude Code, подписи тревоги, установка хуков
  http.rs          локальный HTTP/1.1
  platform/        захват экрана (портал + PipeWire), уведомления, блокировка, BlueZ, трей, тема иконок
  ui/              интерфейс на egui (§16)
```

Вся логика живёт в одном цикле событий (`Controller::run`), как главный поток Qt: команды UI,
HTTP, события канала, таймеры режимов, D-Bus и захват приходят сообщениями и обрабатываются по
одному. Интерфейс только читает снимок состояния и шлёт команды; окно можно закрывать и
открывать заново, ядро и трей продолжают работать.

## Кроссплатформенность

| | Linux (KDE/Wayland) | Windows | macOS |
|---|---|---|---|
| Колонка | RFCOMM-сокет по MAC или `/dev/rfcommN` | RFCOMM-сокет по MAC или COM-порт | последовательный порт сопряжённой колонки (`/dev/cu.…`) |
| Изображения, галерея, живые режимы, Claude, HTTP, CLI | да | да | да |
| Трансляция экрана | портал ScreenCast + PipeWire | xcap | xcap |
| Визуализатор | PipeWire (монитор выхода) | cpal (loopback) | cpal (вход) |
| Сейчас играет, уведомления, блокировка, батарея | D-Bus | нет | нет |
| Трей | StatusNotifierItem (ksni) | tray-icon | tray-icon |

Проверено вживую только на Linux; под Windows код проходит проверку типов (`./build.sh --windows`).

## Тесты и отладка

`cargo test --lib` — протокол (тест-векторы, контрольная сумма, пакеты, окно zstd 2^17 и размер в
заголовке), канал на имитации колонки (запрос данных, повтор чанка, «последний побеждает»), сцены
Claude против эталонных GIF, сессии Claude и хуки, ротация, галерея, настройки, медиа, режимы.

Проверка без глаз — как у эталона: `GET /frame/device`, `GET /frame/<режим>`, `GET /device`,
`POST /live/<id>`, `/state/<s>`, `/notify`.
