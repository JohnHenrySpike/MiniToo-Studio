# MiniToo Studio: спецификация устройства и приложения

Документ описывает колонку **Divoom MiniToo** и всё, что умеет и как выглядит приложение **MiniToo Studio** (сейчас C++20 / Qt 6 / QML, KDE Plasma на Wayland). Цель: по нему можно заново реализовать то же самое на другом стеке, не изучая исходники и интернет.

Эталонная реализация лежит в `/home/spike/projects/divoom`. Если она доступна, пиксельные данные (сцены Claude, иконки, шрифт) удобнее переносить из файлов, указанных в §17, а не перерисовывать по описанию. Всё остальное — протокол, логика, тексты, раскладка — описано здесь полностью.

Состояние на 2026-10-09 (коммит `9aa84b2`). Всё, что помечено «проверено», проверено на реальной колонке пользователя.

## 1. Устройство и транспорт

| Параметр | Значение |
|---|---|
| Модель | Divoom MiniToo: колонка в виде маленького бежевого ретро-компьютера с LCD |
| Экран | **160×128** пикселей, RGB888, ориентация обычная (строки сверху вниз) |
| Bluetooth-имя | `Divoom MiniToo-App` |
| MAC (у пользователя) | `B1:21:81:05:E2:65` |
| Транспорт | Bluetooth Classic, **RFCOMM (SPP), канал 1**; сопряжение не требуется |
| Адаптер хоста | CSR-донгл `00:1A:7D:DA:71:15` (не важно для реализации) |
| Хост | CachyOS, KDE Plasma (Wayland), shell fish |
| BLE | у колонки нет BLE-стороны |
| Аудио | отдельно A2DP/HFP. Через HFP BlueZ узнаёт заряд батареи |

Поведение:

- Колонка иногда «дремлет», и `connect()` возвращает `EHOSTDOWN`. Это нормально: повторять подключение с паузой.
- Через 30 минут без активности колонка выключается сама (`AutoPowerOff: 30` в её конфиге). Проверено: служебный пинг раз в 60 с не даёт ей уснуть.
- Колонка **сама проигрывает многокадровые анимации** (до 92 кадров), присланные одной передачей. На этом построена вся экономия трафика (§8.1).
- Одна передача занимает ~0,3 с почти независимо от размера: фиксированные накладные расходы важнее байтов. Фото 35 КБ при паузе между пакетами 2 мс идёт ~0,8 с, пиксель-арт ~0,5 с.

## 2. Протокол

Основан на [hass-divoom](https://github.com/d03n3rfr1tz3/hass-divoom) (класс Divoom128) и [divoom-minitoo](https://github.com/bugzmanov/divoom-minitoo). Детали ниже проверены на этой колонке (прошивка MiniToo, октябрь 2026).

### 2.1. Кадр сообщения (в обе стороны)

```
01 | len LE16 | cmd | args... | checksum LE16 | 02
```

- `len` = `len(args) + 3`, то есть cmd + args + 2 байта контрольной суммы.
- `checksum` = сумма всех байтов от `len` (оба байта) до конца `args` включительно, `& 0xFFFF`, little endian.
- Экранирования нет.

Тест-вектор: яркость 50 (`0x74 0x32`) → `01 04 00 74 32 aa 00 02`.

Длинное сообщение (медиа-чанк, args 263 байта по `0xFF`): сумма маскируется до 16 бит, длина кадра 1+2+1+263+2+1.

### 2.2. Разбор входящих кадров

Поток из сокета накапливается в буфере:

1. Найти байт `0x01` и отбросить всё до него.
2. Прочитать `len` (LE16). Если `len < 3` или `len > 4096`, это не начало кадра: сдвинуться на 1 байт.
3. Дождаться `len + 4` байт. Последний байт должен быть `0x02`, иначе сдвинуться на 1.
4. Тело = байты `[3 .. 3+len-2)` = cmd + args.
5. Типичный ответ колонки: `04 <эхо cmd> 55 <data>`. Его разбирают как событие `(cmd = второй байт, data = после 0x55)`. Иначе событие `(cmd = первый байт, data = остальное)`.

### 2.3. Передача изображения или анимации (cmd `0x8B`)

**Полезная нагрузка (payload):**

```
25 | frames (1 байт) | speed_ms BE16 | rows=08 | cols=0A | zlen BE32 | zstd(...)
```

- `rows`/`cols` — размер в ячейках 16×16: 128/16 = 8 строк, 160/16 = 10 столбцов. Подтверждено: с `08 0A` картинка встаёт на весь экран правильно. Вариант 8×8 = 128×128 был ошибкой ранних заметок.
- `speed_ms` — длительность каждого кадра в мс (1..65535), одна на все кадры.
- Сжимаются подряд идущие кадры, каждый RGB888 построчно (160·128·3 = 61 440 байт).
- zstd: **windowLog = 17** (у декодера колонки маленькое окно), **content size flag = 1** (размер в заголовке кадра обязателен). Уровень от 1 до 22.
- Лимиты: **≤ 92 кадра** и **≤ 307 200 байт** сжатых данных. Если не помещается, кадры равномерно прореживаются (`i * count / keep`), а `speed` увеличивается в `count/keep` раз, чтобы общая длительность сохранилась. Цикл прореживания: `keep = max(1, min(keep-1, keep * 307200 / zsize))`, пока не влезет или не останется 1 кадр.

**Пакетирование:**

```
start:  00 | total_len LE32                       (args команды 0x8B)
chunk:  01 | total_len LE32 | seq LE16 | ≤256 байт payload
```

Каждый пакет отправляется отдельным сообщением `makeMessage(0x8B, packet)`. `seq` начинается с 0. Тест: payload 600 байт даёт 4 пакета: `00 58 02 00 00`, затем чанки с `seq` 0, 1, 2; последний несёт 88 байт.

**Управление потоком:**

1. Отправить start-пакет.
2. Ждать до 2 с ответа `04 8b 55 00` («давай данные»). Если не пришёл, всё равно слать (записать в журнал).
3. Слать чанки подряд с паузой `chunkDelay` (по умолчанию 2 мс; 0 мс тоже работало). После каждого чанка неблокирующе читать сокет.
4. Колонка может попросить чанк повторно: `04 8b 55 01 <seq LE16>`. Переслать `packets[1+seq]`. Бюджет повторов равен числу пакетов.
5. После последнего чанка подождать хвост: 150 мс для обычной картинки, 40 мс для потоковой. В это время обслуживать повторы.

За всё время запросов на повтор не было ни разу. После каждой передачи колонка присылает `bd 13 …`; это нормально, игнорировать.

**Глубина цвета** (только для трансляции экрана, ради сжатия): каждый пиксель квантуется на месте, формат остаётся RGB888.

- RGB565: `r=(r&0xF8)|(r>>5); g=(g&0xFC)|(g>>6); b=(b&0xF8)|(b>>5)`
- RGB444: `c=(c&0xF0)|(c>>4)`

### 2.4. Известные команды

| cmd | args | смысл |
|---|---|---|
| `0x01` | JSON (UTF-8, compact) | JSON-команды, см. ниже. Колонка шлёт сюда же свои JSON |
| `0x06` | — | GET, ответ — 1 байт «уровня». **Это не батарея**: `0x64` в чужих заметках оказался контрольной суммой |
| `0x08` | `<0..15>` | установить громкость |
| `0x09` | — | GET громкости → `<0..15>` |
| `0x0A` | `<0/1>` | пауза / воспроизведение (AVRCP плееру, который играет через колонку) |
| `0x0B` | — | GET: играет ли (`1` = играет) |
| `0x12` | `<0/1>` | предыдущий / следующий трек |
| `0x13` | — | GET источника звука: 0 Bluetooth, 1 FM, 2 Line-in, 3 SD |
| `0x15` | — | GET: есть ли SD-карта |
| `0x18` | `yy%100, yy/100, MM, dd, HH, mm, ss, 00` | установить время колонки |
| `0x32` | (от колонки) | подтверждение яркости |
| `0x50` | `<icon> <len> <utf8 ≤128>` | встроенное всплывающее уведомление. **Прошивка рисует только значок, текст игнорирует** |
| `0x72` | `01 01 <red LE16> <blue LE16>` | встроенное «табло» со счётом |
| `0x72` | `02 01 00 00 00 00` | встроенный шумомер |
| `0x74` | `<0..100>` | яркость экрана |
| `0x76` | — | GET имени → `<len> <utf8>` |
| `0x8B` | см. §2.3 | изображение или анимация |
| `0xA0` | `01 00` / `01 01` / `01 05` | встроенные игры (тетрис, «игра 2», «игра 3») |
| `0xA0` | `00 00` | выйти из игры |
| `0xBD` | `2B` | GET сведений об устройстве |
| `0xBD` | `18` | GET канала при включении |
| `0xF7` | (от колонки) | периодический «пульс» (`Nob…`), игнорировать |

Коды значков для `0x50`: Divoom 13, Telegram 18, WhatsApp 7, Discord 20, Instagram 1, Facebook 3, Messenger 15, Twitter 4, Skype 9, VK 17, WeChat 11, TikTok 19.

JSON-команды (`0x01`):

- `{"Command":"Channel/SetBrightness","Brightness":N}` — яркость. Приложение шлёт её **вместе** с `0x74`.
- `{"Command":"Channel/OnOffScreen","OnOff":0|1}` — выключить или включить экран.
- `{"Command":"Lyric/Enter"}` — встроенный экран «космонавт».
- `{"Command":"Photo/Enter"}` — встроенная галерея колонки.

Что колонка присылает сама:

- После подключения: JSON `{"Command":"Sys/DevUpdateConf", "AutoPowerOff":30, "Time24Flag", "DateFormat", "BluetoothAutoConnect", "NotificationSound", …}` и `Channel/SetBrightness`.
- Периодически: `Tomato/…` (снимок встроенного помидора, неинтересно), `0xF7` (пульс), `bd 13` (после каждой передачи).

> ⚠️ **Никогда не отправлять** `0x40`, `0xA3`, `0xA4`, `0xAD`, `0xAE` (команды сна). Колонка зависает до отключения питания.

### 2.5. Чего протокол не умеет

- **Скачать картинку с колонки нельзя.** Все команды изображений (`0x44`, `0x49`, `0x8B`, `0x8C`, `0x8D`, `0xB1`, …) работают только на запись. Ближе всего `0x8E` (список 4-байтовых FileId) и `0xB6 FF` (число элементов), но это идентификаторы облака Divoom, а не пиксели. Поэтому историю отправленного хранит само приложение (галерея, §6.3).
- **Заряд батареи по SPP не передаётся.** Проверены все документированные GET и JSON-догадки. Единственный путь — профиль Hands-Free: BlueZ выставляет `org.bluez.Battery1.Percentage`, когда колонка подключена как аудио (§13.2).

Потоки: UI/логика в главном потоке. Сокет — в своём потоке. Захват экрана и звук — в PipeWire thread loop. Мониторинг уведомлений — в отдельном потоке с приватным D-Bus-соединением.

Кодирование медиа (zstd) выполняется в потоке worker'а, а не в UI.

## 4. Что показывает колонка: модель состояний

Это главная часть логики. Разные источники хотят на экран одновременно, и приложение решает, кто сейчас на нём и что вернуть потом.

### 4.1. Состояние

```
mode          ∈ {idle, image, screen, live, claude}   — что пользователь выбрал
activeLive    — объект живого режима (когда mode = live)
overlayActive — временная карточка или проверка на экране (с таймером)
interrupted   — тревога Claude поверх не-Claude режима
away          — экран компьютера заблокирован
deviceContent — {frames, speed}: последнее, что отправлено на колонку
idleContent   — что было на экране в режиме idle до того, как его закрыли
lastManual    — {frames, speed}: последнее отправленное изображение (mode = image)
liveJob       — id передачи живого режима, которая сейчас идёт (или 0)
livePending   — у живого режима есть новые кадры, ждут освобождения канала
```

Режимы:

- **idle** — приложение ничего своего не шлёт; на экране остаётся то, что было.
- **image** — отправлена картинка или GIF.
- **screen** — идёт трансляция экрана.
- **live** — показывается живой режим (или ротация).
- **claude** — показывается сцена текущего состояния Claude.

### 4.2. Правила

**`deviceLive()`** — чей живой контент сейчас идёт на колонку: если `away`, то режим «часы» (clock), иначе `activeLive` при `mode == live`, иначе ничего.

**`submit(frames, speed, level, depth, streaming)`** — единственная точка отправки медиа. Запоминает `deviceContent = {frames, speed}`, обновляет зеркало колонки в UI (кадры, скорость, ревизию) и `lastSentFrame` для `/frame/device`. Отдаёт задачу worker'у и возвращает id.

**`submitLive()`**:

```
mode = deviceLive(); если нет — выйти
если overlayActive или interrupted или liveJob ≠ 0: livePending = true; выйти   // «последний побеждает»
livePending = false
frames, step = mode.deviceFrames()
liveJob = submit(frames, step, level = mode.streaming ? 3 : 9, Full, streaming = mode.streaming)
```

Когда передача `liveJob` завершилась: `liveJob = 0`. Если `livePending` и есть `deviceLive()` и нет оверлея и тревоги, снова вызвать `submitLive()`.

Каждый живой режим сообщает «мои кадры для колонки изменились» (`deviceFramesChanged`). Если это `deviceLive()`, вызывается `submitLive()`.

**Оверлей** — карточка уведомления, конец этапа Pomodoro, проверка сцены:

```
beginOverlay(ms): saveIdleContent(); overlayActive = true; пауза трансляции; пауза ротации; таймер ms
по таймеру:       overlayActive = false; restoreContent()
showOverlay(frame, ms): beginOverlay(ms); submit([frame], 1000, level 9)
```

**`saveIdleContent()`**: если нет ни оверлея, ни тревоги, ни блокировки, `idleContent = deviceContent`. Нужно потому, что idle ничего своего не шлёт и вернуть «как было» можно только из запомненного.

**`restoreContent()`** — вернуть то, что должен показывать текущий режим:

```
обновить паузу ротации (пауза = interrupted || overlayActive || away)
если overlayActive: выйти
если interrupted:   показать сцену alerting (с подписью); выйти
если away:          submitLive() (часы); выйти
mode = screen:      снять паузу трансляции
mode = idle:        если idleContent есть — переотправить его (иначе ничего: возвращать нечего)
mode = image:       переотправить lastManual
mode = claude:      показать сцену текущего состояния
mode = live:        submitLive()
```

**`setMode(m)`**:

- Если `m ≠ live`: остановить ротацию и освободить `activeLive`.
- Запомнить `live/onStart` (id режима или пусто) и `claude/modeOnStart`.
- Если `m ≠ claude`: сбросить «показанную сцену» и «состояние сцены», остановить таймер смены сцен.

Ручные действия пользователя (отправить картинку, начать трансляцию, включить Claude, выбрать живой режим) сбрасывают `interrupted = false`.

### 4.3. Тревога Claude поверх других режимов

`applyClaudeState()` вызывается через 250 мс после изменения состояния или списка сессий. Таймер склеивает всплески PreToolUse/PostToolUse.

```
state = агрегированное состояние Claude
если mode = claude и не away:
    если нет оверлея: showFace(state)        // showFace сам пропускает повтор той же сцены с той же подписью
    выйти
// другие режимы, а также Claude-режим за часами блокировки: прерывает только тревога
если не claudeInterrupt и mode ≠ claude: выйти
alerting = state == "alerting"
если alerting и не interrupted и (mode ≠ idle или away):
    saveIdleContent(); interrupted = true; пауза трансляции; пауза ротации
    если нет оверлея: показать сцену alerting
иначе если alerting и interrupted и нет оверлея и подпись изменилась:
    показать сцену alerting заново          // спрашивает другая сессия или о другом
иначе если не alerting и interrupted:
    interrupted = false; сбросить «состояние сцены» (следующая тревога получит новую сцену); restoreContent()
```

Важно: в режиме **idle** без блокировки тревога экран **не** прерывает.

### 4.4. Блокировка экрана

См. §12. Коротко: пока экран заблокирован, на колонке часы с приглушённой яркостью, выбранный режим не меняется, а тревоги и уведомления проходят поверх часов.

### 4.5. Таблица приоритетов (сверху важнее)

1. Оверлей (уведомление, Pomodoro, проверка) — на своё время, потом `restoreContent`.
2. Тревога Claude (interrupted). В режиме claude сцена alerting показывается и так.
3. Часы блокировки (away).
4. Контент режима (image / screen / live / claude / idle).

## 5. Канал связи (worker)

Поток владеет сокетом.

**Входящие вызовы** (потокобезопасно, через mutex + condition variable):

- `configure(mac, channel, chunkDelay, keepalive)` — смена MAC или канала разрывает связь и подключается заново.
- `setWantConnected(bool)` — при `true` пропустить паузу повтора.
- `submitMedia(job) → id` — **«последний побеждает»**. Если предыдущая задача ещё не начата, она заменяется и о ней сообщается `mediaSent(id, ok=false)`.
- `submitCommand(cmd, args)` — очередь по порядку.

**Цикл:**

1. Если связи нет, а она нужна, подключиться:
   - Неблокирующий `connect`, ожидание 12 с. Затем блокирующий сокет с `SO_SNDTIMEO = 3 с`.
   - После успеха: пауза 300 мс, слить входящее, состояние Connected, лог «подключено».
   - При ошибке: пауза 2, 4, 8, … до 30 с; лог «нет связи с колонкой: <ошибка> (повтор через N с)».
2. Если связь есть и есть работа:
   - Слить входящее (заодно заметить обрыв).
   - Отправить все команды, пауза 20 мс между ними.
   - Отправить медиа (§2.3) и сообщить `mediaSent(id, bytes, frames, ms, ok)`.
3. Если работы нет и прошло `keepalive` секунд (по умолчанию 60, 0 = выкл.): отправить `0x09` и `0x06` (дешёвые GET).
4. **Обрыв** (ошибка send или recv, POLLHUP):
   - Закрыть сокет, состояние Disconnected, лог «связь потеряна, переподключаюсь».
   - Сразу новая попытка.
   - Незавершённую медиа-задачу вернуть в очередь, если там нет более новой. Иначе сообщить о ней `ok=false`.
5. `want = false`: закрыть сокет, лог «отключено».

**Состояния:** `0` нет связи, `1` подключение, `2` подключена.

При переходе в Connected приложение запрашивает сведения: `09, 0b, 13, 76, 06, 15`, затем `bd 2b`, `bd 18`.

**Разбор ответов** в «сведения об устройстве» (`deviceInfo`):

| Ответ | Ключ |
|---|---|
| `09` | `volume` |
| `0b` | `playing` |
| `13` | `workMode` |
| `15` | `sdCard` |
| `06` | `level06` |
| `76` | `name` |
| `32` | `brightnessAck` |
| JSON | `json:<Command>` (объект целиком) |
| `bd XX` | `ext_XX` |
| `f7` | `heartbeat` |
| прочее | `op_XX` (hex) |

Последние 100 «интересных» кадров (без `f7`, `bd 13`, `Tomato/*`) хранятся с временем для диагностики. Ответы `8b` (управление потоком) не логируются.

## 6. Изображения и галерея

### 6.1. Загрузка

- Форматы: png, jpg/jpeg, gif, webp, bmp, svg, avif, jxl, heic, tif/tiff. Всё, что умеет системный декодер; формат определяется по содержимому.
- Учитывается EXIF-ориентация.
- Анимация: до 600 кадров. У каждого кадра своя задержка (если 0, то 100 мс). У одиночного кадра задержка 1000.
- Средняя задержка `averageDelay = max(20, сумма/кол-во)`.

### 6.2. Рендер в 160×128

Холст 160×128 залит чёрным. Режимы:

- **Кадрировать** (`fit=0`, по умолчанию): берётся прямоугольник `crop` в нормированных координатах источника (0..1) и растягивается на весь холст. Рамка в UI держит пропорцию 5:4. По умолчанию — наибольший центрированный 5:4 прямоугольник.
- **Вписать** (`fit=1`): масштаб с сохранением пропорций по центру, поля чёрные.
- **Растянуть** (`fit=2`): без сохранения пропорций.

Масштабирование: **пиксель-арт** = ближайший сосед (без сглаживания), иначе сглаживание (bilinear/smooth).

Автовыбор при первом открытии файла: если источник ≤ 160×128, включается пиксель-арт.

**Отправка:** кадров не больше 92, лишние прореживаются (`frames[i * count / keep]`), `speed = averageDelay * count / keep`. Уровень zstd из настроек (по умолчанию 19), полный цвет. Режим становится `image`, кадры запоминаются в `lastManual`.

Предпросмотр «Так будет на колонке» перерисовывается через 60 мс после последнего изменения настроек.

### 6.3. Галерея (локальная история)

Папка: `~/.local/share/minitoo-studio/MiniToo Studio/gallery/`.

```
<id>.<ext>          копия оригинала (id = SHA-1 содержимого; ext в нижнем регистре, ≤5 символов, иначе "img")
thumbs/<id>.png     миниатюра 160×128 «как на колонке» с последними настройками
cache/<sha1>.png    миниатюры файлов из «своей папки» (ключ: путь|размер|mtime)
index.json
```

```json
{
  "version": 1,
  "folder": "/home/…/Pictures/pixel",          // необязательно
  "items": [                                    // новые первыми
    {
      "id": "…sha1…", "file": "…sha1….gif", "name": "cat.gif", "source": "/orig/path/cat.gif",
      "added": "2026-10-08T12:00:00Z", "lastSent": "2026-10-08T12:05:00Z", "sent": 3,
      "favorite": true, "frames": 24, "width": 320, "height": 256,
      "settings": { "fit": 0, "pixelArt": false, "crop": [x, y, w, h] }
    }
  ]

```

Поведение:

- **Любое открытое** изображение добавляется в галерею, дубликат по хешу не создаётся. Повторное открытие известной картинки восстанавливает её `fit`, `pixelArt` и `crop`.
- Каждое изменение настроек сохраняется с миниатюрой. Запись на диск отложена на 700 мс.
- Отправка увеличивает `sent` и ставит `lastSent`.
- Если открытую картинку удалили из галереи, повторная отправка возвращает её туда.
- Удаление стирает копию и миниатюру. Оригинал не трогается.
- Фильтры: **Все**, **Избранное**, **Папка**. Папка — своя папка пользователя: файлы не копируются, пока их не откроют. До 1000 файлов, сортировка по времени изменения, без рекурсии.
- Перетаскивание нескольких файлов или папки добавляет их все (папка — только файлы верхнего уровня). Если перетащили один файл, он ещё и открывается.
- Миниатюры для файлов, добавленных без открытия, рендерятся лениво с настройками по умолчанию.

## 7. Трансляция экрана

- **Захват:** xdg-desktop-portal ScreenCast + PipeWire. Готовый QScreenCapture на KDE Wayland **не заработал**, поэтому захват свой.
  - Последовательность D-Bus-вызовов: `CreateSession` → `SelectSources` → `Start` → `OpenPipeWireRemote`.
  - Параметры `SelectSources`: `types = 1|2` (мониторы и окна), `persist_mode = 2` (до отзыва), `cursor_mode = 2` (встроенный курсор, если доступен), `restore_token` (если есть).
  - Каждый запрос несёт `handle_token`. Подписаться на `org.freedesktop.portal.Request.Response` по пути `/org/freedesktop/portal/desktop/request/<sender>/<token>` **до** вызова.
  - `restore_token` из ответа `Start` сохраняется (`screen/restoreToken`). В следующий раз диалог выбора не показывается.
- **PipeWire:** форматы BGRx, BGRA, RGBx, RGBA; не чаще 15 кадров/с. Кадр копируется с учётом stride.
- **Устаревший портал.** После обновления системы долгоживущий бэкенд портала держит старые `.so` (в `/proc/<pid>/maps` они видны как `(deleted)`), и диалог выбора не открывается. Приложение проверяет процессы портала пользователя: `xdg-desktop-portal(-kde|-gnome|-gtk|-wlr|-hyprland)`. Если находит такие, показывает плашку с кнопкой «Перезапустить» → `systemctl --user restart <unit>`. Для KDE юнит `plasma-xdg-desktop-portal-kde.service`.
- **Область:** нормированный прямоугольник 5:4 по картинке источника (та же рамка, что для кадрирования). Сохраняется вместе с размером источника и восстанавливается, только если размер совпал. Иначе берётся центр 5:4.
- **Поток:**
  - Таймер `1000/fps` (1–20 к/с, по умолчанию 5).
  - Кадр: область → 160×128 (Crop, «чёткие пиксели» = ближайший сосед).
  - Одинаковый кадр не шлётся повторно, но не реже раза в 5 с.
  - Следующий кадр готовится только после того, как предыдущий доставлен.
  - zstd `min(level, 6)`.
  - Качество: **Максимум** = RGB888, **Баланс** = RGB565 (по умолчанию), **Скорость** = RGB444.
  - Каждые 2 с считается фактический fps, показывается размер кадра.
- **Пауза:** оверлеи, тревога и блокировка ставят трансляцию на паузу. При снятии паузы кадр отправляется сразу.
- Если захват прекратился, режим `screen` переходит в `idle`.

## 8. Живые режимы

### 8.1. Общий контракт

- У режима есть `id`, `title`, `subtitle`, `icon`, строка `status` (для UI) и текущий кадр 160×128.
- **Подсчёт ссылок:** `acquire()` / `release()`. Режим работает (таймеры, сеть, D-Bus), пока у него есть хотя бы один пользователь: колонка, предпросмотр на странице «Режимы» (пока страница видна, захвачены все режимы) или часы блокировки. Первый `acquire` запускает режим и сразу рисует кадр.
- **`publish(frame)`**: если кадр байт в байт совпал с предыдущим, ничего не делать. Иначе сохранить, поднять ревизию, уведомить UI и (по умолчанию) сообщить `deviceFramesChanged`.
- **`deviceFrames(&stepMs)`** — что слать на колонку. По умолчанию это один текущий кадр.
- **Минута вперёд.** Режим, который знает своё будущее (часы, Pomodoro, «Сейчас играет»), отдаёт сразу пачку кадров с шагом 1000 мс. Колонка проигрывает её сама, и тогда передача нужна раз в минуту, а не раз в секунду. Такой режим сам решает, когда сообщать `deviceFramesChanged` (он «владеет» этим сигналом).
- **Потоковый режим** (визуализатор): `streaming = true`, zstd 3, короткий хвост ожидания.
- Остальные живые режимы: zstd 9, полный цвет.

**Холст:**

- Шрифт **DejaVu Sans** (моно: DejaVu Sans Mono), размер в пикселях, full hinting, сглаживание включено (кроме оговорённых мест).
- Акцентный цвет `#d97757` (терракота Claude).
- `bar(rect, value, fill, bg=#232837)` — скруглённая полоса прогресса.
- `elide(text, px, bold, width)` — обрезка с многоточием.

### 8.4. Сейчас играет (`nowplaying`)

**Метаданные:**

- Заголовок: «Сейчас играет».
- Подзаголовок: «обложка и трек из любого плеера (MPRIS)».
- Иконка: `music`.

**Опрос** раз в 1 с:

- Перебрать сервисы `org.mpris.MediaPlayer2.*` на сессионной шине.
- Взять первый в состоянии `PlaybackStatus == Playing`, иначе первый с данными.
- Прочитать `Properties.GetAll("org.mpris.MediaPlayer2.Player")` (таймаут 500 мс): `Metadata` (`xesam:title`, `xesam:artist[]` через «, », `xesam:album`, `mpris:length` в мкс, `mpris:artUrl`), `PlaybackStatus`, `Position` в мкс.
- `Identity` взять из `org.mpris.MediaPlayer2`. Если пусто, то 4-я часть имени сервиса.
- **Обложка:** `file://` загружается с диска, `http(s)` — по сети. Ответ принимается, только если URL обложки за это время не сменился.

**Позиция «движется ли»** (некоторые плееры, например Firefox, не обновляют `Position`):

```
stuck = (position == previous) ? stuck + 1 : 0
если не играет или stuck ≥ 3: moves = false
иначе если stuck == 0:      moves = true
```

**Когда слать на колонку:**

- Если ключ тот же и трек движется → слать при перемотке (позиция отличается от ожидаемой больше чем на 2 с) или когда до конца отправленной минуты осталась 1 с.

## 11. Статус Claude Code

### 11.1. Источник: хуки Claude Code

Кнопка «Установить хуки» правит `~/.claude/settings.json`:

1. Сначала резервная копия `settings.json.minitoo-backup-yyyyMMdd-HHmmss`.
2. Если JSON некорректен, хуки не ставятся и показывается ошибка.
3. Для каждого события `SessionStart, SessionEnd, UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop`: убрать старые свои записи (с любым портом), сохранить чужие, добавить группу с командой.

```json
{ "hooks": { "<Event>": [ { "hooks": [ { "type": "command",
  "command": "curl -s -m 2 -X POST -H 'Content-Type: application/json' --data-binary @- http://127.0.0.1:47800/hook >/dev/null 2>&1 || true" } ] } ] } }
```

- **Своя запись** — команда содержит `curl`, `127.0.0.1:` и `/hook`.
- **«Удалить хуки»** убирает свои записи (тоже с резервной копией), пустые группы и события.
- **«Установлены»** = во всех 7 событиях есть своя запись с текущим портом.
- **«Скопировать JSON»** кладёт сниппет в буфер; он же показан в поле только для чтения.

### 11.2. События → состояние сессии

Тело хука — JSON со stdin хука: `hook_event_name`, `session_id`, `cwd`, `message`, `notification_type`, `tool_name`.

| Событие | Состояние |
|---|---|
| `SessionStart`, `Stop` | `chilling` (отдыхает) |
| `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PreCompact`, `SubagentStart` | `working` (работает) |
| `Notification`, `PermissionRequest` | `alerting` (ждёт вас); см. исключение ниже |
| `SessionEnd` | сессия удаляется |
| `SubagentStop`, прочее | без изменений |

- **Исключение для «ждёт ввода».** `notification_type == "idle_prompt"` или текст содержит «waiting for your input» (Claude напоминает о себе после 60 с простоя). Тревогой это считается, только если включено «“Ждёт ввода” после простоя — тоже тревога» (`claude/idleAlerts`, по умолчанию **выключено**). Иначе состояние сессии не меняется (новая сессия — chilling).
- **`PermissionRequest` без message** → message = «Claude needs your permission to use <tool_name>».
- **Хранение message.** Сообщение сессии сохраняется, если оно непустое или состояние не alerting. Так тревога без текста не стирает прежний вопрос.

**Сессия** = `{id, cwd, state, lastEvent, message, updated}`. Проект = имя последней папки `cwd`. Если `cwd` нет — первые 8 символов id. Для ручной проверки — «проверка».

**Агрегированное состояние** = самое тревожное: `alerting > working > chilling`. Если сессий нет — `chilling`.

**Таймауты** (проверка раз в 10 с):

- `working` дольше 15 мин без событий становится `chilling` (упавшая сессия не «крутится» вечно);
- сессия старше 3 ч без событий удаляется.

### 11.4. Какая сцена показывается

- **Набор:** у каждого состояния свои галочки (`claude/scenesOff/<state>` — список выключенных). Минимум одна сцена всегда остаётся.
- **Выбор при входе в состояние** — «мешок»: каждая включённая сцена по разу в случайном порядке до повторов, и никогда та же два раза подряд.
- **Смена по таймеру:** раз в `claude/sceneMinutes` минут (0 = нет; в UI 0–60, по умолчанию 5) новая сцена, если состояние не менялось. Кроме alerting, свой GIF или меньше двух сцен.
- **Свой GIF** для состояния (`claude/face/<state>` = путь) заменяет все его сцены:
  - кадрирование 5:4 по центру;
  - пиксель-арт, если ≤ 160×128;
  - ≤ 92 кадра;
  - задержки масштабируются.
- **Отправка сцены:** скорость = средняя задержка, zstd из настроек (19), полный цвет. Одна и та же сцена с той же подписью повторно не отправляется.

### 11.5. Подпись на сцене «Ждёт вас»

Включено по умолчанию (`claude/alertCaption`). Только для alerting.

- **Строка 1** — проект самой свежей тревожной сессии. Если тревожных несколько, плюс « +N».
- **Строка 2** — что спрашивают, сокращённо:
  - «… needs your permission to use X» → «Разрешить X?»
  - содержит «waiting for your input» → «Ждёт ответа»
  - содержит «needs your attention» → «Нужно ваше внимание»
  - пусто → «Ждёт вас»
  - иначе текст как есть (пробелы схлопнуты).

**Рисование на каждом кадре сцены:**

- Внизу полоса высотой `2·10+3 = 23` px, `rgba(0,0,0,200)`.
- Строки в y = 106 и 116, отступ 4 px.
- Строка 1 цветом акцента, светлее на 20%; строка 2 белым.
- Текст переводится в верхний регистр и рисуется пиксельным шрифтом 5×7 (§17.1) с обрезкой «…» по 152 px.
- Если в шрифте нет какого-то символа — DejaVu Sans 9 px жирным, с обрезкой.

Пример: «ПРОВЕРКА» / «РАЗРЕШИТЬ BASH?».

### 11.6. Проверки

- **«Проверить: Работает / Ждёт вас / Отдыхает»**:
  - На 10 с создаётся фиктивная сессия `manual`. Для alerting сообщение «Claude needs your permission to use Bash».
  - Список сессий и трей следуют за ней.
  - Колонка в **любом** режиме показывает сцену как оверлей на 10,4 с, потом возвращает прежнее.
  - В режиме claude (без блокировки) сцену показывает обычная логика.
- **«Показать на колонке» у карточки состояния** — оверлей 10 с с текущей сценой этого состояния. Щелчок по миниатюре сцены делает её текущей и показывает так же.
- **«Очистить»** — удалить все сессии.

## 12. Блокировка экрана

**Источник:** сигнал сессионной шины `org.freedesktop.ScreenSaver` `/ScreenSaver` `ActiveChanged(bool)`. Его шлют KDE и другие окружения.

**Блокировка** (если включено «Показывать часы и приглушать яркость», `away/enabled`, по умолчанию да):

1. `saveIdleContent()`.
2. `away = true`.
3. Захватить режим «часы» (refcount).
4. Пауза трансляции.
5. Яркость `away/brightness` (по умолчанию 15%).
6. Пауза ротации.
7. Если нет оверлея и тревоги — отправить часы.
8. `applyClaudeState()`: в режиме claude тревога прорвётся поверх часов.

Лог: «экран заблокирован: часы, яркость N%».

**Разблокировка:**

1. `away = false`.
2. Вернуть яркость.
3. В режиме claude сбросить `interrupted`.
4. `restoreContent()`.
5. Отпустить часы.
6. `applyClaudeState()`.

**Яркость:** обычная, изменённая во время блокировки, не отправляется до разблокировки. Изменение «яркости при блокировке» применяется сразу, если экран заблокирован. Выключение опции снимает блокировку.

**Проверено** имитацией сигнала: часы показались при режиме claudestats, тревога с подписью встала поверх часов и ушла, после «разблокировки» вернулась статистика.

**Как тестировать, не блокируя экран:** послать сигнал адресно процессу приложения.

```
dbus-send --session --dest=:1.NNN --type=signal /ScreenSaver org.freedesktop.ScreenSaver.ActiveChanged boolean:true
```

Здесь `:1.NNN` — уникальное имя приложения на шине. **Никогда не вызывать `Lock`.**

### 13.1. Управление

| Действие | Команды |

Встроенный экран колонки закрывает кнопка на самой колонке или любая отправка картинки из приложения.

### 13.2. Батарея (BlueZ)

- Раз в 30 с (и через 1 с после запуска) вызвать `org.bluez` `/` `ObjectManager.GetManagedObjects` на системной шине.
- Найти `org.bluez.Device1` с `Address == MAC` и запомнить его путь. Заряд: `org.bluez.Battery1.Percentage`. Если такого интерфейса нет, заряд неизвестен (−1).
- «Подключена как аудио» — под путём устройства есть `MediaControl1.Connected == true` или объект `MediaTransport1`.
- Кнопка **«Подключить как аудио»** → `Device1.Connect()` (таймаут 30 с), через 3 с повторный опрос. После этого колонка становится звуковым выходом, и HFP сообщает заряд. Проверено: заряд появился.
- Изменение заряда пишется в журнал: «заряд колонки: N%».

### 13.3. Поиск колонки

Кнопка «Найти»: классический Bluetooth-поиск на 15 с. Устройства с «Divoom» в имени показываются первыми. Щелчок подставляет MAC.

## 14. HTTP API, командная строка, единственный экземпляр

### 14.1. HTTP-сервер

**Только `127.0.0.1`**, порт `claude/port` (по умолчанию **47800**).

- Минимальный HTTP/1.1: читается заголовок до `\r\n\r\n` и тело по `Content-Length`. Запросы больше 4 МБ обрываются.
- Ответ всегда с `Connection: close`.
- Если порт занят — лог «HTTP-сервер: порт N занят», в UI красный светодиод.

| Метод и путь | Тело | Действие / ответ |
|---|---|---|
| `POST /hook` | JSON хука | обработать событие (§11.2) → `{"ok":true}`; не объект → 400 |
| `POST /state/<working\|alerting\|chilling>` | — | фиктивная сессия `manual` в этом состоянии (без таймера) |
| `POST /mode/<claude\|idle>` | — | включить режим Claude или idle (idle также останавливает трансляцию) |
| `POST /live/<id>` | — | показать живой режим: `clock`, `sysmon`, `nowplaying`, `pomodoro`, `claudestats`, `github`, `visualizer` |
| `POST /show` | `{"path","fit":"crop\|fit\|stretch"}` | открыть файл и отправить |
| `POST /notify` | `{"app","summary","body","icon"}` | карточка-оверлей (app по умолчанию «minitoo») |
| `POST /raw` | hex-строка «cmd args…» | отправить как есть |
| `POST /activate` | — | показать окно |
| `GET /status` | — | `{"state":"…","sessions":[{id,project,cwd,state,event,message,updated(ISO)}]}` |
| `GET /device` | — | `{connected, info{…}, frames[…], mode, live, liveFramesSent, lastTransfer}` |
| `GET /frame/<id\|device>` | — | PNG текущего кадра режима или последнего отправленного на колонку; 404, если нет |

Пример: `curl -X POST -d '{"app":"build","summary":"Сборка готова","body":"0 ошибок"}' http://127.0.0.1:47800/notify`

### 14.2. Командная строка

```
minitoo-studio                      окно + трей
minitoo-studio --hidden             сразу в трей
minitoo-studio --send f.gif [--fit crop|fit|stretch]   через запущенное приложение (/show), иначе напрямую
minitoo-studio --mode claude|idle   переключить запущенное приложение
minitoo-studio --state working|alerting|chilling
minitoo-studio --status             JSON /status
minitoo-studio --no-device          не подключаться при запуске
minitoo-studio --image f.png        открыть картинку при запуске
minitoo-studio --debug              журнал в правой панели, диагностика протокола, «пульс»
minitoo-studio --screenshot DIR     (отладка) снимки всех страниц в обеих темах, без колонки
minitoo-studio --export-faces DIR   (скрыто) GIF и лист всех сцен Claude
```

- **Прямой `--send`** без запущенного приложения: свой worker с MAC, каналом, паузой и уровнем zstd из настроек, без keepalive. Печатает «sent: N bytes, F frames, T ms»; ожидание до 60 с.
- **Единственный экземпляр:** при запуске `POST /activate` на свой порт. Если ответили, напечатать «MiniToo Studio is already running» и выйти.

### 14.3. Запуск приложения

`startup()`:

1. Применить настройки связи и запустить worker.
2. Запустить HTTP.
3. Если включено «Подключаться при запуске» — подключиться.
4. Открыть последнюю картинку (`image/last`), если файл существует.
5. Если `claude/modeOnStart` — включить Claude.
6. Если `live/rotationOnStart` и есть отмеченные — запустить ротацию с `live/onStart`. Иначе, если задан `live/onStart`, показать этот режим.

Закрытие окна при «Сворачивать в трей» (и наличии трея) только прячет его. «Выход» из трея завершает приложение.

## 16. Интерфейс: дизайн-язык и страницы

Первая версия со стандартной страницей «Режимы» пользователю не понравилась. Он попросил интерфейс «в стиле самой колонки», и всё было переделано под этот стиль.

### 16.1. Идея

Окно выглядит как сама MiniToo:

- бежевый пластик корпуса;
- серые клавиши с ходом (нажатая утапливается);
- одна оранжевая клавиша для главного действия;
- тёмные шильдики с разрядкой капителью, как «MINITOO» под экраном;
- пиксельные надписи и иконки, как на её экране;
- справа нарисована сама колонка, её экран повторяет настоящий, а клавиши и ручка работают.

Есть ночная тема. Колонка справа в ней остаётся бежевой.

### 16.3. Примитивы

- **Plastic** — выпуклая деталь.
  - Прямоугольник цвета `edge` во всю высоту, поверх «лицо» цвета `face` высотой `height − depth` (depth 2–9, обычно 3).
  - Тонкий блик (1 px, `face` светлее на 7%) у верхнего края лица, с отступом 0,6 радиуса.
  - Нажата: лицо сдвигается вниз на `depth − 1`, блик пропадает.
- **Well** — утопленное поле.
  - Цвет `well`, рамка 1 px `wellLine`; в фокусе рамка 2 px `accent`.
  - Внутренняя тень: полоска 2 px чёрного у верхнего края, прозрачность 7% (ночью 25%).
- **Plate** — шильдик.

- **PixelText** — «пиксельный» текст.

  - Обрезка «…» по ширине; выравнивание.
- **PixelIcon** — иконка 12×12 из ASCII-шаблона: `#` основной цвет, `+` дополнительный (по умолчанию основной с прозрачностью 45%). Увеличение в целое число раз. Неизвестное имя → иконка из системной темы.
- **PageHeader** — пиксельная иконка ×3, заголовок PixelText 12 px ×2, подзаголовок обычным текстом; справа кнопки страницы.

## 19. Подводные камни и выводы

1. **Экран 160×128, а не 128×128.** Заголовок медиа `rows=8, cols=10`.
2. **zstd: окно 2^17 и размер в заголовке обязательны.** Иначе колонка не декодирует.
3. **Каждая передача стоит ~0,3 с.** Анимацию до 92 кадров колонка проигрывает сама, а повторяющиеся кадры сжимаются почти в ноль. Всё, что предсказуемо на минуту вперёд, надо слать минутой. Секундный тик часов был ошибкой первой версии: 60 передач в минуту вместо одной.
4. **«Последний побеждает»** для медиа и отдельный флаг «кадры ждут канал» для живых режимов. Иначе очередь растёт, и колонка показывает прошлое.
5. **Idle ничего своего не шлёт.** Чтобы вернуть экран после оверлея, запоминать последнее отправленное до того, как экран закрыли. Если с запуска ничего не отправлялось, возвращать нечего.
6. **`0x06` — не батарея.** Заряд только через HFP и BlueZ `Battery1`.
7. **Команды сна `0x40 0xA3 0xA4 0xAD 0xAE` вешают колонку** до отключения питания.
8. **`0x50` показывает только значок**, поэтому текст рисуется своей карточкой.
9. **Картинки с колонки не скачать**: история только своя.
10. **`EHOSTDOWN` при подключении** — колонка дремлет; повтор с паузой до 30 с.
11. **QScreenCapture на KDE Wayland не работает** — нужен свой портал с PipeWire и restore token. После обновления системы портал может держать удалённые библиотеки; это надо обнаруживать и предлагать перезапуск.
12. **Мелкий векторный текст без сглаживания превращается в кашу** — отсюда ручной шрифт 5×7.
13. **MPRIS-плееры могут не обновлять `Position`** (Firefox): гистерезис «стоит после 3 одинаковых опросов», иначе передачи пойдут каждую секунду.
14. **Мониторинг уведомлений** — только через `BecomeMonitor` на приватном соединении, и после этого не отправлять в него ничего.
15. **Блокировка экрана**: `org.freedesktop.ScreenSaver.ActiveChanged`. Тестировать адресным сигналом, никогда не вызывать `Lock`.
16. **Claude Code:**
    - `idle_prompt` через 60 с простоя по умолчанию не тревога;
    - `PermissionRequest` может прийти без текста;
    - всплески Pre/PostToolUse склеивать (250 мс);
    - зависшую в «работает» сессию отпускать через 15 мин.
17. **Тревога в idle** (без блокировки) экран не прерывает — так задумано.
18. **Режим снимков** пишет пользовательские настройки — запускать с копией конфига.
