One little screen, many jobs

MiniToo Studio talks to the speaker directly over Bluetooth RFCOMM and keeps its screen busy: anything predictable is sent a minute ahead, so the speaker plays it on its own.

Pictures and GIFs

PNG, JPEG, GIF, WebP, APNG, SVG, JPEG XL and more. A draggable 5:4 crop frame, pixel-art scaling and a local gallery with favourites.

Screen mirroring

Pick a monitor or a window through the desktop portal and stream an area of it at up to 20 fps.

Live modes

Clock and weather, system monitor, now playing, Pomodoro, Claude Code statistics, GitHub Actions and an audio visualizer — alone or in a rotation.

Claude Code status

Working, resting or waiting for you — with the project name and the question. 18 pixel animations and a short tune for every change.

Notifications

Desktop notifications appear as cards with the sender's icon, on top of whatever is showing.

Screen lock

When the computer locks, the speaker shows a clock and dims; after unlocking everything comes back as it was.

Speaker control

Brightness, volume, playback, screen on/off, clock sync, battery level and the speaker's built-in screens and games.

Scriptable

A local HTTP API and a command line: send a picture from a script, switch modes, push a card from your build.

English and Russian

24/12-hour time and date formats; translations are plain text files you can add yourself.

Screenshots

The interface looks like the speaker itself: plastic panels, keys with travel, pixel text — in a beige and a night theme.

Claude Code on your desk

One click installs hooks into ~/.claude/settings.json (with a backup, leaving your other hooks alone). From then on the speaker shows what Claude is doing — and rings when it needs you, with the project name and the question: “Allow Bash?”.

18 scenes, drawn pixel by pixel on a 40×32 grid, six for each state — or your own GIF. Running subagents show up too.

8-bit tunes from the speaker itself (when it is connected as audio), four to choose from per state.

Usage statistics: tokens, sessions and plan limits as a live mode, in six looks.

Alerts can break through pictures and streams, so a question never waits unnoticed.

Install

You need a Divoom MiniToo and a Bluetooth adapter. Pairing is not required: on the first start open Settings, put in the speaker's MAC address or press Find.

From a release

Download minitoo-studio-vX.Y.Z-linux-x86_64.tar.gz from Releases, then:

tar xzf minitoo-studio-*-linux-x86_64.tar.gz
cd minitoo-studio-*-linux-x86_64
./minitoo-studio

…or from source

In a container, with only Docker on the host — or with a local toolchain (Rust 1.88+, PipeWire headers, clang, pkg-config):

./build.sh                 # → build/minitoo-studio
cargo build --release      # or without Docker

App menu and autostart

Adds MiniToo Studio to the application menu and, with --autostart, starts it hidden in the tray on login. Closing the window keeps the app running in the tray.

./packaging/install-desktop.sh --autostart   # --uninstall to undo

Scriptable

The app listens on 127.0.0.1:47800, local only. The same things work from the command line.

RequestWhat it does
POST /showopen a file and send it
POST /notifyshow a notification card
POST /live/<id>show a live mode
POST /mode/<claude|idle>give the screen to Claude, or release it
GET /statusClaude state, sessions and subagents
GET /frame/devicePNG of what the speaker shows

A card when your build finishes:

curl -X POST -d '{"app":"build","summary":"Build finished","body":"0 errors"}' \
     http://127.0.0.1:47800/notify

A picture from a script, through the running app:

minitoo-studio --send cat.gif --fit crop

Platforms

Linux with KDE Plasma on Wayland is the main target and is tested on a real speaker. The Windows build is type-checked but not tried on a device yet; macOS is untested.
